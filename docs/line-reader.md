# LineReader

## 职责

LineReader 是整个项目的文件读取基础设施，负责高效地从磁盘文件中逐行读取文本内容。它不关心行的内容是什么（JSON 还是其他格式），只负责把文件切成一行一行的字符串交给上层使用。它明确不负责 JSON 解析、数据过滤或任何业务逻辑。

## 文件组成

| 文件 | 说明 |
|------|------|
| `include/LineReader.h` | 类接口声明，包含所有成员变量和方法签名 |
| `src/LineReader.cpp` | 具体实现，包含缓冲区管理、行提取逻辑 |

## 核心类

### LineReader

**职责**：封装 C 标准库的文件操作，在其上实现一个带 64KB 缓冲区的逐行读取器。之所以不直接用 C++ 的 `std::getline`，是因为 C 标准库的 `fread` 配合手动缓冲区在大文件场景下 I/O 性能更好。

**关键成员变量**：
- `FILE* file_`：底层 C 文件指针，以二进制模式打开，避免操作系统自动转换换行符
- `char* buffer_`：堆上分配的 64KB 读取缓冲区，每次从磁盘批量读入数据存放于此
- `size_t bufferPos_`：当前在缓冲区中已读到的位置，相当于一个游标
- `size_t validBytes_`：本次从磁盘读入后缓冲区中实际有效的字节数
- `std::string currentLine_`：正在拼接中的当前行内容（当一行跨越两次缓冲区填充时需要拼接）
- `bool hasUnfinishedLine_`：标记 `currentLine_` 中是否有尚未输出的半行内容

**核心方法**：

#### `std::string output()`

这是最核心的方法，每次调用返回文件中的下一行（不含换行符）。

工作流程：
1. 先检查缓冲区当前位置是否还有未处理的数据；如果缓冲区已耗尽，调用 `fillBuffer()` 从磁盘再读一批
2. 在缓冲区中从当前位置向后扫描，寻找 `\n` 或 `\r\n` 的位置
3. 如果在缓冲区内找到了行尾，把从上次停止位置到行尾之间的内容拼接到 `currentLine_`，然后清空 `currentLine_` 并返回这一行
4. 如果扫描到缓冲区末尾还没找到行尾（说明这一行很长，跨越了缓冲区边界），把当前缓冲区剩余内容追加到 `currentLine_`，然后重新填充缓冲区，继续寻找行尾
5. 如果文件已到末尾且 `currentLine_` 中还有内容（文件最后一行没有换行符的情况），直接返回 `currentLine_` 中的内容

这种设计保证了无论行有多长，都能正确处理，同时通过批量 I/O 避免了每行都触发一次系统调用的性能问题。

#### `bool fillBuffer()`

从磁盘读取最多 `bufferSize_`（默认 64KB）字节到 `buffer_` 中，更新 `validBytes_` 和 `bufferPos_`，并在到达文件末尾时设置 `fileEof_` 标志。

#### `bool hasNextLine() const`

判断是否还有更多行可读。只有当缓冲区已耗尽、文件已到末尾、且没有未输出的半行内容时，才返回 false。

#### `void reset()`

将文件指针重新定位到文件开头，并清空所有缓冲区状态，使得可以重新从头读取文件。

**注意事项**：
- 拷贝构造和拷贝赋值被显式禁用，因为文件指针不适合被复制（两个对象共享同一个文件句柄会导致状态混乱）
- 支持移动语义，可以安全地转移所有权
- 析构函数会自动关闭文件并释放缓冲区内存

## 与其他模块的交互

- **依赖**：仅依赖 C 标准库（`<cstdio>`），无其他项目内部依赖
- **被依赖**：`StockDataBatchReader`、`FullFileLoader`、`FastCodeExtractor` 都通过 `LineReader` 读取文件

## 数据流

```
磁盘文件
   │  fread（每次最多 64KB）
   ▼
char* buffer_（内存缓冲区）
   │  扫描 \n / \r\n
   ▼
std::string currentLine_（行拼接缓冲）
   │  output() 调用
   ▼
调用方（一行 JSON 字符串）
```
